#50 — New Directory Screen: Two-Panel Agent × Hotel Command Centre

What & Why
The current Directory screen shows five hotel cards as the primary navigation. 
This was correct when hotels were the only unit of navigation. After Tasks #48 
and #49, the meaningful unit is an agent-at-a-hotel pair — some agents are in 
crawl at one hotel but not activated at others. The hotel-card view hides this 
entirely. The new Directory replaces the card grid with a two-panel layout that 
makes the full operational picture visible at a glance, without any new backend 
endpoints.

Left panel (Agent Registry) — technical admission status by agent, CO-owned.
Right panel (Hotel Operations) — operational phase status by hotel, GM-owned.
Both panels are click-through to the relevant deep UI.

No backend changes. This task is entirely in VdaOS.jsx and uses only existing 
endpoints.

──────────────────────────────────────────────────────────────────────────────
Done looks like
──────────────────────────────────────────────────────────────────────────────
The Directory route renders a two-panel layout (not the hotel card grid).

Left panel fetches:
  GET /api/onboarding?source=vda_native   → VDA native agent rows
  GET /api/onboarding?source=a2a_external → External A2A agent rows

Right panel fetches:
  GET /api/dashboard/phases/portfolio     → hotel-level summary
  GET /api/agent_phases (all companyIds)  → per-agent per-hotel phase cells

Clicking a VDA native agent row opens its EXCEPTION_AUTHORITY.md detail view 
(File Manager filtered to that agentId).

Clicking an External A2A agent row opens the 8-step wizard at that agent's 
current step.

Clicking a hotel name in the right panel navigates to that hotel hub (existing 
behaviour — same as clicking the old card).

Clicking a phase cell (e.g. "🟡 crawl") opens Phase Management for that 
agent at that hotel.

Clicking "Activate →" on a native agent row opens a hotel picker modal and 
calls POST /api/dashboard/activation/start for the selected hotel.

The old hotel card grid (Property Directory) is removed from the Directory 
route. Hotel cards still exist inside each hotel hub — only the root directory 
changes.

Steps
──────────────────────────────────────────────────────────────────────────────
1. Remove the Property Directory section from VdaOS.jsx
   Delete the JSX that renders the "Property Directory" title, the subtitle, 
   the "5 CONFIGURED PROPERTIES" label, and the hotel card grid (the 
   COMPANIES.map block that renders hotel cards at the root directory view). 
   The COMPANIES array and individual hotel hub logic are NOT deleted — only 
   the root directory card grid render.

2. Build the two-panel Directory component
   Replace the deleted section with a new <DirectoryScreen> component defined 
   within VdaOS.jsx (no new file needed). 

   Data fetching (all on mount, parallel):
     const [nativeAgents, setNativeAgents] = useState([])
     const [externalAgents, setExternalAgents] = useState([])
     const [portfolio, setPortfolio] = useState(null)
     const [allPhases, setAllPhases] = useState({})  
       // { 1: [...phases], 2: [...phases], ... } keyed by companyId
     const [matrixOpen, setMatrixOpen] = useState(false)
     const [activateModal, setActivateModal] = useState(null)  
       // null | { agentId, agentName }

   Fetch all five companyId phase lists in parallel:
     Promise.all([1,2,3,4,5].map(cid => 
       fetch(`/api/dashboard/phases?companyId=${cid}`)
         .then(r => r.json())
         .then(d => [cid, d.phases])
     )).then(entries => setAllPhases(Object.fromEntries(entries)))

   Helper: getAgentPhase(agentId, companyId)
     Returns the phase string for that agent+hotel from allPhases, 
     or "not_activated" if no record exists.

3. Left panel — VDA Native Agent rows
   Map over nativeAgents array. For each agent:
   - Derive the agent icon from agentCard.name using the same icon map 
     as AGENT_DEFS in VdaOS.jsx (reuse existing icon logic).
   - Derive the overall status badge from onboarding_requests.status.
   - Render 5 hotel dots using getAgentPhase(agentId, companyId) for 
     companyIds 1–5.
   - Render "Activate →" or "Manage →" based on whether any hotel has 
     phase "not_activated".
   - On "Activate →" click: setActivateModal({ agentId, agentName }).

4. Left panel — External A2A Agent rows
   Map over externalAgents. Render status badge from status field.
   "Review →" onClick: setActiveTab("onboarding") (navigate to Agent 
   Onboarding tab, Wizard sub-tab).

5. Right panel — Compact hotel list
   Map over COMPANIES array. For each hotel:
   - Pull portfolio.summary[company.id] for counts.
   - Build summary string from walkRunCount + totalAgents.
   - "Open hub →" onClick: setSetup(company) (same navigation as old card).

6. Right panel — Matrix view toggle
   When matrixOpen === true, render the matrix grid below the compact list.
   Use CSS grid: 6 columns (hotel label + 5 agent columns... wait, 
   actually rows=hotels, cols=agents). 
   Use a horizontally scrollable container since 8 columns may overflow.
   Column headers: abbreviated agent names from AGENT_DEFS.
   Cells: call getAgentPhase(agentId, companyId) for each combination.
   Cell onClick for activated phases: navigate to Agent Onboarding → 
     Phase Management sub-tab filtered to that agent+hotel.
   Cell onClick for "not_activated": open activateModal for that agent, 
     pre-selecting that hotel.

7. Activate modal
   Renders as an overlay when activateModal is not null.
   Title: "Activate [agentName] at which hotel?"
   Five hotel buttons using COMPANIES array.
   Grey out hotels where getAgentPhase(activateModal.agentId, companyId) 
     !== "not_activated".
   On hotel click:
     POST /api/dashboard/activation/start
     body: { agentId: activateModal.agentId, companyId, initiatedBy: role }
     On success: close modal, refetch nativeAgents + allPhases.
     On error: show inline error message in modal.

8. Styling
   Use the existing dark theme CSS vars from VdaOS.jsx throughout.
   Left and right panels: same card/border style as existing hub cards.
   Status badges: use existing badge pattern (coloured dot + text).
   Hotel dots in left panel: 14px coloured circles, spaced 6px apart, 
     with a 1-letter label (B L M P V) as tooltip on hover.
   The matrix cells: 80×40px minimum, centred content, hover highlight.
   Panel headers ("Agent Registry" / "Hotel Operations"): same section 
     label style as existing sub-tab section headers.

9. Verify
   - Directory renders without errors for all 6 role types 
     (Ambassador through Compliance Officer).
   - Native agents from seed show with correct status badges.
   - External Apaleo Smart Pricing Agent shows with "CO Review 2" badge.
   - Portfolio summary shows correct hotel count (5).
   - Matrix toggle expands/collapses correctly.
   - "Open hub →" on Berlin navigates into Berlin hub correctly.
   - "Activate →" for checkout-agent opens modal with 5 hotel options; 
     BER shows active/greyed if already activated.
   - Role banner still shows at top of Directory (do not remove it).
